# Гибридная архитектура ML Research

Дата обзора: 27 октября 2026 года.

Реализация развивает собственное ядро `ml_lab`, сохраняя исследовательские наборы, временную подготовку и разделение train / validation / test. Сторонний код в этой итерации не копировался; проекты ниже использованы как архитектурные ориентиры по опубликованным README. Проверка их исходных реализаций и лицензий нужна перед будущим переносом кода.

| Источник | Полезный подход | Реализация в лаборатории |
|---|---|---|
| [Prediction Playground](https://github.com/sushant-mishra-dtu/Prediction-Playground) | Последовательный процесс данных, настройки, оценки и объяснения | Четыре основные вкладки; генерация кандидатов, Optuna и SHAP через собственное ядро |
| [Teachable Machine](https://github.com/Mohammed-Lr/teachable-machine) | Настраиваемые модели классического ML и нейросети | Декларативный каталог; настройки MLP, LSTM, GRU, RNN |
| [Feature-Lab](https://github.com/Hat-GitBot/Feature-Lab) | Исследование данных и интерактивная визуализация | Профиль колонок, корреляции, распределения и графики Plotly |
| [Auto-ML-Service](https://github.com/Shawn-Son/Auto-ML-Service) | Единый процесс и HTML-отчёт | Автономный HTML с test-метриками, validation-сравнением, прогнозами и конфигурацией |
| [Local AutoML](https://github.com/hirakparekh/AutoML) | Независимое ML-ядро, Pipeline, пространства моделей | Существующие core.py, model_registry.py, ui.py подключены к единому интерфейсу |
| [MLWorkbench](https://github.com/Hiranmayee-ABSN/MLWorkbench) | Хранение экспериментов и отделение вычислений | SQLite-журнал метаданных; FastAPI пока не добавлен |

## Хранение и воспроизводимость

`.local/experiments.sqlite3` хранит UTC-время, модель, признаки, метрики, размеры частей, идентификатор данных и настройки каждого успешного запуска. Журнал не сохраняет модель или полные данные; для повторного обучения нужен исходный датасет. Полный обученный pipeline скачивается отдельно. Нечисловые метрики сериализуются как JSON null. HTML экранирует имена колонок и другие пользовательские значения.

Победитель выбирается по R² (регрессия) или F1 macro (классификация) на validation. Test оценивается после выбора. История не является рейтингом между разными датасетами. Данные обрабатываются локально; журнал сохраняется автоматически после успешного обучения.

## Библиотеки

Текущее ядро уже использует Streamlit, pandas, NumPy, scikit-learn, PyTorch, Optuna, SHAP, Plotly, openpyxl, joblib и requests. SQLite входит в Python. HTML-отчёт не требует отдельной библиотеки.

XGBoost/CatBoost/LightGBM, Darts/skforecast, MLflow и редактор публикационных графиков Matplotlib пока не интегрированы. Добавление этих библиотек без адаптеров моделей и проверки совместимости не даёт работающих возможностей, поэтому requirements.txt не расширен необязательными зависимостями.
