- `lab4.ipynb`: по 9 кодовых ячеек, исследовательский формат, а не отдельный сервер сайта.
- `lstm_autotuner.py`, `2025/MAML.py` и базовый MUF CSV в двух папках побайтово совпадают; остальные проверенные скрипты имеют различия. Не следует импортировать оба дерева как независимые библиотеки.

## Методологические решения

1. HP-фильтр на всём ряду использует будущие измерения. Он не перенесён в прогнозный конвейер.
2. В части исходников LSTM получает форму `(строки, признаки, 1)`. В новой версии временное окно состоит из последовательных строк с формой `(строки, окно, признаки)`.
3. Используются три части: train / validation / test. Генератор выбирает победителя по R² (регрессия) или F1 macro (классификация) на validation; только победитель оценивается на test. Модель после выбора не переобучается, чтобы сохранить проверенный экземпляр.
4. Скейлеры, заполнение пропусков и кодировщики обучаются только на train. MLP и LSTM дополнительно нормируют цель по train.
5. При горизонте h признаки строки t соответствуют цели t+h; перед границами валидации и теста исключаются h обучающих строк. Одинаковые временные метки не разделяются между частями.
6. Лаги используют только прошлые значения цели. С лагами оценка пошаговая: фактические прошлые значения становятся доступны по мере движения во времени. Это не рекурсивный прогноз всего будущего блока.
7. При горизонте 0 текущие измерения других станций — входы оценки текущей цели. Для прогнозирования будущего необходимо задать положительный горизонт и убедиться, что входы доступны к моменту прогноза.
8. Точное совпадение колонки с целью отмечается в интерфейсе; такая колонка не выбирается по умолчанию. Предметные зависимости и менее очевидные утечки требуют проверки исследователем.

### Реализация в лаборатории

В `ml_lab/repair.py` добавлена собственная причинная обработка: IQR, MAD или Z-score относительно **предыдущего** окна; необязательные физические min/max; ограничение значений границами либо замена и восстановление. Пропуски восстанавливаются последним известным значением или линейной экстраполяцией по двум предыдущим принятым наблюдениям с учётом реального datetime. Восстановленные точки не становятся самостоятельными опорными наблюдениями экстраполяции. Предусмотрен предел длины разрыва.

Все строки с корректным datetime остаются в подготовленном наборе. Начальные пропуски без истории и разрывы сверх установленного предела остаются неизвестными. Оставшиеся пропуски обычных X заполняются внутри pipeline по train; для неизвестного Y или недоступной выбранной истории строка не может участвовать в соответствующем эксперименте. Некорректный datetime обрабатывается отдельно, как и раньше.

Глобальные средние, двусторонняя интерполяция и HP-фильтр исходников не перенесены в прогнозную подготовку: они могут использовать правую часть ряда. IsolationForest также не обучается на всём наборе: в текущем интерфейсе представлены три оконных статистических детектора, а не этот алгоритм. Числовые скейлеры Standard/Robust/MinMax обучаются только на train.

При восстановлении Y обучение может использовать восстановленные метки, но validation/test оцениваются **только по исходным измерениям Y**. Исходные аномальные измерения не скрываются из метрик. В результатах отдельно указаны число измеренных фактов и число восстановленных Y в train. Прогнозы для неизвестных фактов сохраняются без выдуманной оценки качества.

Признаки строятся для выбранных числовых X и/или Y: произвольные положительные лаги, rolling mean/std/min/max/median/IQR, среднее изменение между концами прошлого окна, EWM и разности с разными лагами. Каждый признак истории использует данные не позднее t−1. Флаги пропусков/аномалий Y также сдвигаются назад. Добавлены недельные sin/cos и признак выходного дня.

Будущий прогноз использует тот же код восстановления и признаков, с историей в качестве контекста. Для истории X требуется файл с исходными будущими X. История Y и флаги качества Y не дают безусловного прогноза неизвестного будущего; такие входы блокируются. Обработка носит пошаговый характер: новые фактические прошлые измерения становятся доступными по мере движения по validation/test.

Ridge, Random Forest, Extra Trees, HistGradientBoosting, MLP, LSTM и GRU обучаются отдельно для каждой числовой колонки по предыдущим измерениям и календарным признакам. Используется ограниченное прошлое обучающее окно, заданный интервал повторного обучения и лимит числа обучений. И обучающие метки, и опорная история исключают восстановленные и аномальные значения. Текущая целевая колонка не попадает во входы восстановителя другой колонки. Резервный метод и ошибки обучения отражаются в диагностике; точность на искусственно скрытых точках автоматически не заявляется. API повторно использует подготовленные данные при неизменном источнике и настройках.

## Модельные детекторы аномалий

В `ml_lab/anomaly_detection.py` добавлены IsolationForest, LOF в режиме novelty, OneClassSVM и EllipticEnvelope. Они обучаются на ограниченных прошлых исходных измерениях каждой колонки и пакетно оценивают новые строки без включения этих строк в то же обучающее окно. Независимая обработка ошибок отдельных запросов сохраняет причинность: патологическая более поздняя точка не меняет способ оценки ранних точек того же пакета. Найденные аномалии заменяются и передаются существующему восстановителю. Для крайне удалённых значений предусмотрена явно учитываемая защита по прошлому IQR; почти постоянные окна и ошибки обучения диагностируются отдельно.
