# ML Research

## Описание моделей, экспорт результатов и журнал

Основная работа собрана во вкладке **«Эксперимент»**. Внутри находятся схема исследования, настройки данных, модели и результаты. Схема открывается первой: узлы отображают путь от исходного набора через предобработку и обучение к оценке. Выберите узел, чтобы просмотреть его данные и настройки; библиотека содержит дополнительные EDA-графики, диагностику ошибок, permutation importance, SHAP, Integrated Gradients и экспорт артефактов. Соединения управляют схемой эксперимента, а настройки данных и модели сохраняют подробные формы соседних под-вкладок.

Отдельная вкладка **«Описание моделей»** доступна до обучения. Выберите одну или несколько моделей, добавьте текущую модель или семейства последнего эксперимента. Для каждой доступны теория, основная формула, концептуальная схема, параметры и сигнатура установленного класса. Для нейросетей отображаются размеры слоёв/окон; для последней обученной модели используются её фактические параметры. Для поддерживаемого дерева/ансамбля отдельно показано реальное дерево с ограничением глубины (в ансамбле — первое).

Каталог, статусы библиотек и проверка онлайн-версий перенесены в отдельную вкладку **«Каталог и источники»**. Во вкладке **«Описание моделей»** автоматически извлекаются краткий текст и до четырёх иллюстраций выбранного официального раздела: материалы загружаются в фоне и появляются без блокировки обучения. При недоступности сети сохраняется локальная теория и архитектурная схема. Изображения документации описывают алгоритм; фактическая структура обученного дерева показывается отдельно. Ссылки ведут на официальный API и теоретический раздел разработчиков. Встроенный просмотр API включается отдельно; при ограничениях сайта используйте внешнюю ссылку. Кнопка обновления проверяет версии пакетов на PyPI. Локальные схемы и теория работают без интернета; схема устройства не показывает все обученные веса.

Во вкладке результатов **«Экспорт»** нажмите **«Подготовить архив результатов»**. ZIP содержит метрики train/validation/test, прогнозы и дневные метрики, таблицу кандидатов, конфигурацию, рассчитанные объяснения, интерактивные HTML-графики (работают офлайн), JSON с точными данными/оформлением, описание и DOT-схему модели. Для поддерживаемых деревьев включается реальная структура в DOT. Обученную модель можно включить в архив отдельной опцией. Графики используют сохранённое оформление; выбранный ROC-класс и локальная SHAP-строка учитываются. Новые объяснения ради экспорта не рассчитываются.

Во вкладке **«Журнал»** кнопка **«Очистить журнал»** удаляет все записи экспериментов из SQLite и историю текущей сессии. Текущая модель, результаты, архивы и датасеты сохраняются. Экспорт JSON доступен перед очисткой.

## Восстановление данных и новые признаки

На первой вкладке появился раздел **«Восстановление пропусков и аномалий»**: выбор колонок, экстраполяция по прошлым точкам или перенос предыдущего значения, поиск IQR/MAD/Z-score по прошлому окну, ограничение или замена аномалий, физические min/max и предел длины разрыва. Обработка включена по умолчанию для временных данных; её можно отключить. Категории Y классификации не интерполируются.

В **«Результат восстановления · до и после»** показаны счётчики исправлений, график с аномальными точками и экспорт подготовленного CSV. Исходный график остаётся исходным. Начальные пропуски без истории не восстанавливаются будущими значениями; неизвестные X дополнительно заполняются статистиками train. Восстановленные Y могут участвовать в train, но метрики считаются только по исходным измерениям. Источники и методические ограничения описаны в [docs/source_analysis.md](docs/source_analysis.md).

В **«Признаки истории и горизонт»** выбираются колонки X/Y для лагов, скользящих mean/std/min/max/median/IQR/trend, EWM и разностей. Дополнительные лаги вводятся числами через запятую. Все эти признаки используют только прошлое. В окне доступен режим неполной начальной истории. Нормализация X выбирается отдельно: StandardScaler, RobustScaler, MinMaxScaler или без масштабирования; параметры обучаются на train.

## Оформление графиков

Над каждым графиком расположен раскрываемый редактор **«Оформление · название графика»**. Можно задать заголовок, подписи X/Y (отдельно для каждой панели), сетку по обеим или одной оси либо убрать её, цвет и толщину сетки, тему, размер шрифта и легенду. Для рядов доступны цвета, толщина/штриховка линий, размер маркеров и режим линий/точек. Для тепловых карт — цветовая шкала, для SHAP waterfall — цвета положительных, отрицательных и итоговых вкладов.

Изменения применяются кнопкой **«Применить оформление»**, исходный вид возвращает **«Сбросить оформление»**. Для изменения цветов рядов включите **«Использовать выбранные цвета»**. Настройки каждого графика сохраняются в текущей сессии, включая переключение вкладок и временное скрытие графика. Оформление не изменяет datetime, значения данных, прогнозы или метрики. График будущего прогноза также сохраняется в результате, чтобы редактирование оформления не требовало повторного расчёта.

## Графики результатов и объяснимости

- **Качество и прогноз:** две панели временного хода train и test. На каждой — исходный факт, прогноз обученной модели и базовый прогноз. Временной график заменяет прежнюю диаграмму «факт–прогноз». Train показывает качество подгонки, test — независимую оценку. Базовая модель для временной регрессии использует предыдущее значение цели с учётом восстановления, для случайного разбиения — медиану train, для классификации — наиболее частый класс train. Дополнительно доступны остатки против прогноза, распределение ошибок, абсолютная и накопленная ошибка, автокорреляция. Для классификации — матрицы ошибок, показатели по классам и вероятностные диагностики при наличии predict_proba.
- **Обучение и метрики:** метрики по дням представлены двумя соседними панелями train/test. Для регрессии MAE, RMSE и R² — сгруппированные столбцы со штриховкой, MAPE (%) — линия на правой оси. MAE/RMSE имеют единицы Y, R² безразмерен: сравнивать высоту разных метрик напрямую нельзя. Неопределённые значения не заменяются нулями. Для классификации показаны столбцы Accuracy и F1 macro. Кривые loss отображаются для моделей, которые сохраняют историю обучения.
- **Сравнение моделей:** validation-рейтинг, история поиска и качество относительно времени обучения. Победитель определяется без использования test.
- **Объяснимость:** важность перестановок, SHAP с локальным waterfall и зависимостью от значения признака, Integrated Gradients для рекуррентных сетей. Объяснения рассчитываются на validation и не доказывают причинность.
- **Экспорт:** прогнозы test, временной ход train, конфигурация, модель и HTML-отчёт.

В начале каждого раздела приведено пояснение интерпретации. Под каждым графиком результатов добавлена краткая подсказка: что отображается, как читать оси и какие изменения говорят об улучшении или проблеме. Для сохранённых до обновления результатов без train-прогнозов необходимо повторное обучение. Расчёт train-прогнозов не переобучает модель и не меняет сохранённый контекст рекуррентной сети для test. Восстановленные Y не подменяют исходные факты ни на графиках, ни при вычислении метрик.

## Индекс времени

В интерфейсе графики и обучение используют индекс `datetime` (`pandas.DatetimeIndex`). Он сохраняется в X, Y, валидационных и тестовых прогнозах, включая классификацию. При горизонте h индекс прогнозов соответствует времени целевого значения. Позиции строк используются отдельно для разбиения и непрерывности окон.

Если в файле нет datetime или date + time, задайте известные начальную дату, время и шаг измерений и подтвердите создание индекса. До этого обучение недоступно. Присутствующий DatetimeIndex также поддерживается. Сама дата служит индексом; в модель передаются выбранные числовые/категориальные X и календарные признаки.

### React-интерфейс

Новый интерфейс использует React + TypeScript, Tailwind CSS, компоненты в стиле shadcn/ui, Lucide, React Flow, AG Grid, Plotly.js, React Resizable Panels и Framer Motion. Python ML-ядро остаётся backend и вызывается через FastAPI. Рабочая область исследования открывается первой: слева компактная библиотека из пяти реализованных инструментов, в центре редактируемый холст, справа настройки выбранного узла, снизу изменяемая по размеру панель входных/выходных данных, профиля и графиков. Схемы сохраняются локально; вычисления используют тот же sklearn pipeline и записывают запуск в журнал SQLite. Каталог моделей, обзор данных, самостоятельный эксперимент, результаты, журнал и темы остаются доступны через навигацию. Подготовка данных доступна в разделе «Данные»: настройки времени, восстановление рядов, признаки истории и фактическое разбиение выборок используют общее Python-ядро со Streamlit. Остальные возможности интерфейса продолжают развиваться; наличие конкретных элементов описано ниже. Исходный `app.py` и ML-ядро сохранены без изменений.

Результаты каждого шага появятся в нижней панели. «Сохранить» запишет схему локально; список сохранённых схем находится рядом с кнопками действий. ### Подготовка данных в React

В разделе **«Данные»** выберите или загрузите набор; ссылка **«Подготовка данных ↓»** переводит к настройкам ниже исследовательской панели. Здесь доступны:

- цель Y и тип задачи; исходный график с выбором нескольких числовых рядов;
- чтение дат, исключение некорректного времени, создание datetime из начала и шага, единая сетка и обработка повторных временных меток;
- календарные признаки, восстановление по прошлым значениям, поиск IQR/MAD/Z-score, физические границы и индикаторы качества;
- лаги произвольной длины, скользящие mean/std/min/max/median/iqr/trend, EWM, разности, неполные окна и горизонт;
- выбор X с кнопками «Выбрать все» и «Снять все», профиль и таблица подготовленного набора;
- масштабирование и заполнение оставшихся X внутри обучающего pipeline;
- разбиение по времени или случайное, размеры в процентах или строках, тест за один день или диапазон дней, фактические размеры и счётчики незадействованных строк.

Настройки пересчитывают предпросмотр без обучения модели. В **«Результат восстановления · до и после»** показаны счётчики исправлений, исходный и восстановленный ряды, маркеры аномалий и настройки оформления. **«Подготовленные данные CSV»** выгружает все строки после подготовки, до заполнения и масштабирования X внутри модели. Таблица ограничена первыми 1000 строками; графики охватывают весь период с прореживанием больших наборов, график восстановления сохраняет все обнаруженные аномальные точки.

Нажмите **«Перейти к выбору модели»**: раздел **«Модели и подбор»** использует тот же черновик цели, признаков, подготовки и разбиения. Выбор сохраняется при переходах между разделами в открытом приложении. При смене датасета подготовка и размеры выборок сбрасываются, чтобы колонки предыдущего набора не попадали в новый. Конструктор схем сохраняет собственную конфигурацию узлов.

История, горизонт и восстановление требуют разделения по времени. Скейлер и статистики заполнения X обучаются только на train. Начальные пропуски без истории остаются неизвестными; категории целевой классификации не восстанавливаются. Восстановленные Y могут участвовать в обучении, но метрики сравниваются с исходными измерениями. Для теста по датам фактическое число доступных строк определяется выбранным периодом и одинаково рассчитывается в предпросмотре и при обучении.

### Восстановление с ML-моделью или нейросетью

В **«Данные» → «Восстановление пропусков и аномалий»** выберите способ **«ML-модель или нейросеть»**. Доступны Ridge, Random Forest, Extra Trees, градиентный бустинг, MLP, LSTM и GRU. Этот выбор относится к восстановлению исходного сигнала; алгоритм итогового прогноза по-прежнему выбирается отдельно в **«Модели и подбор»**. Те же настройки доступны в узле предобработки конструктора схем.

Для каждой выбранной числовой колонки строится отдельная регрессионная модель по её предшествующим измерениям, календарным циклам и времени с последних измерений. Другие колонки не используются. Обучающие метки и лаги модели содержат только реальные прошлые значения, не отмеченные как аномалии. Восстановленные точки не становятся новыми обучающими метками. Скейлеры входов и цели обучаются на том же прошлом окне. LSTM и GRU используют последовательности признаков и выполняются на CPU.

Настройте число прошлых измерений, минимум и максимум обучающих примеров, интервал повторного обучения, лимит обучений на колонку и seed. Для деревьев доступны количество и глубина; для MLP — нейроны и итерации; для LSTM/GRU — нейроны, окно и эпохи. Модель впервые обучается при подходящем пропуске после накопления истории, затем при необходимости заново обучается на скользящем прошлом окне. После достижения лимита используется последняя успешно обученная модель.

Нажмите **«Применить поиск и восстановление»**. После изменения параметров примените их снова. Подготовленный результат кэшируется по данным и настройкам: выбор X, расчёт разбиения, CSV и обучение итоговой модели не должны повторно обучать восстановитель при неизменной подготовке. Конструктор выполняет восстановление при запуске схемы.

Если истории недостаточно или прогноз модели недоступен, можно использовать предыдущее значение, линейную экстраполяцию либо оставить пропуск. Начальные пропуски без истории остаются неизвестными. Общий предел длины разрыва и физические границы действуют и для моделей. Чтобы аномалии заменялись моделью, выберите **«Заменить и восстановить»**; **«Ограничить границами»** обрезает значения без модельной замены.

В таблице **«Результат восстановления · до и после»** указаны модель, число значений, восстановленных моделью и резервным способом, число обучений, размер последнего обучающего окна, предупреждения и причины резерва. График и CSV содержат итоговую подготовленную колонку. Эти счётчики не являются оценкой точности: нейросеть не гарантирует преимущество над простыми методами. Категории Y классификации не восстанавливаются; при восстановлении числовой Y метрики итогового прогноза используют исходные измерения.

### Isolation Forest и другие детекторы аномалий

В **«Поиск аномалий»** доступны Isolation Forest, Local Outlier Factor (LOF), One-Class SVM и Elliptic Envelope вместе с прежними IQR/MAD/Z-score. Быстрый вариант — кнопка **«Isolation Forest + восстановление»**: она выбирает Isolation Forest и режим **«Заменить и восстановить»**, сохраняя выбранный восстановитель. Затем нажмите **«Применить поиск и восстановление»**.

Детекторы находят подозрительные значения; численное восстановление выполняет отдельный выбранный способ — предыдущее значение, экстраполяция, ML-регрессия или нейросеть. Для каждого столбца детектор обучается на прошлых исходных измерениях. Текущие и будущие точки не входят в обучающее окно; LOF используется с `novelty=True`. Восстановленные значения не входят в последующие обучающие окна детектора. Физически невозможные и крайне удалённые точки исключаются; остальные исходные статистически подозрительные измерения пересматриваются в новом окне, чтобы пороги не сужались при последовательном отбрасывании хвостов распределения.

Доступны ожидаемая доля аномалий (для One-Class SVM — nu), минимум и размер прошлого окна, интервал обновления в строках, лимит обновлений и seed. Для Isolation Forest настраиваются деревья, для LOF — соседи. Доля не гарантирует такой же процент выбросов в новых данных. Elliptic Envelope предполагает примерно одновершинное нормальное распределение. После лимита используется последнее состояние детектора; до накопления истории проверяются физические границы.

Для крайних значений за пределами прошлого распределения действует дополнительная защита по прошлому IQR; её срабатывания считаются отдельно. При почти постоянном прошлом окне применяется порог отклонения 3% от уровня (минимум 3e-8), при ошибке обучения — резервный IQR. Эти случаи явно указаны в диагностике. Оценка аномалии на графике положительна для найденного выброса; она не является вероятностью и не сравнивается напрямую между разными детекторами.

Настройки доступны также в узле предобработки конструктора. Предпросмотр, экспорт и обучение повторно используют подготовку при неизменных данных и настройках. Пояснения по алгоритмам: [официальное руководство scikit-learn](https://scikit-learn.org/stable/modules/outlier_detection.html).

### Модели и подбор в React

Вкладка **«Модели и подбор»** содержит выбор алгоритма по категории, поиск по названию или библиотеке, описание модели и пояснения к её параметрам. Датасет, цель, X и подготовка задаются в **«Данных»**; на странице модели доступна сводка только для просмотра и ссылка на изменение данных.

- **Ручная настройка** обучает одну конфигурацию с указанными значениями параметров.
- **Исследование диапазонов** позволяет задать границы, целочисленный шаг, логарифмическую шкалу и допустимые категориальные значения. Кнопка **«Сгенерировать модели»** показывает уникальные конфигурации до обучения. Если допустимых комбинаций меньше запрошенного количества, список будет короче. На обучение передаётся именно этот список; после изменения параметров или seed его нужно сгенерировать заново.
- **Автоматическая оптимизация** выполняет заданное число испытаний Optuna TPE. Следующие конфигурации определяются по предыдущим результатам; заранее фиксированного списка нет.

После запуска страница показывает ожидание и время выполнения; индивидуальные результаты отображаются после завершения расчёта. Внизу доступны таблица параметров, статусов, предупреждений и метрик validation, график истории подбора и лучший вариант. Для регрессии подбор максимизирует R², для классификации — F1 macro. Test оценивает итоговую модель и не участвует в подборе. Полная диагностика открывается кнопкой **«Открыть результаты»**.

### Графики результатов и datetime в React

В **«Результатах» → «Качество и прогноз»** режим **«Все выборки»** показывает train, validation и test отдельными панелями. В validation отображается только победившая конфигурация. Ряды охватывают всю соответствующую выборку; для больших наборов точки прореживаются по всему периоду с сохранением экстремумов и границ больших разрывов. Табличные предпросмотры и графики имеют отдельные ограничения: первые 1000 строк таблицы не ограничивают период графика. Через разрывы и между выборками линии не соединяются; для случайного разбиения используются точки.

В **«Обучении»** выберите метрику: дневные графики train, validation и test имеют отдельные оси и пояснения. MAE/RMSE, R² и MAPE не смешиваются на одной шкале. Размер графика пересчитывается при изменении контейнера; полная сборка Plotly поддерживает гистограммы и матрицы диагностики. История подборов и объяснения очищаются при переключении на другой запуск, чтобы не показывать устаревшие графики.

Datetime формируется общим Python-кодом для данных, обучения, прогнозов и дневных метрик:

- **MUF и Athens clean:** готовая колонка `datetime` в формате ISO, год–месяц–день.
- **TEC/CB и Athens raw:** объединение `date` + `time`, затем сортировка по времени. Для исследовательского `DD-MM-YYYY` порядок определяется по всему столбцу; неоднозначные дни не меняют месяц от строки к строке.
- **Колонка только `date`:** временной индекс ежедневных наблюдений.
- **Без календарной даты, например `days` + `time`:** укажите известные начало и шаг в «Данных». Год из номера дня или имени файла автоматически не выдумывается.

Порядок дня и месяца можно изменить вручную. ISO-даты сохраняют порядок год–месяц–день при любом выборе. Часовые пояса приводятся к UTC, время без полной даты не подменяется сегодняшней датой. Некорректные значения исключаются только при включённой соответствующей настройке и учитываются в диагностике. Для горизонта h время прогноза соответствует целевому наблюдению t+h.

Старые сохранённые предпросмотры могли содержать лишь начало каждой выборки и все validation-кандидаты. Для получения полных исправленных рядов таких запусков повторите обучение; интерфейс показывает предупреждение, если полные данные недоступны после перезапуска API.

## Работа с интерфейсом

1. Во вкладке **«Эксперимент» → «Данные и признаки»** выберите пример или загрузите CSV, TSV, XLSX. При необходимости задайте разделитель, кодировку, десятичный знак или лист Excel.
2. Там же выберите цель Y и входные X. Для временных рядов дата определяется автоматически (`datetime` либо `date` + `time`); календарные предикторы создаются из временного индекса. При необходимости добавьте лаги. Данные сортируются по дате. Без даты сохраняется порядок строк.
3. Откройте **«Эксперимент» → «Схема эксперимента»**, выберите блок «Обучение модели» и настройте алгоритм, параметры и стратегию поиска. Для MLP доступны размеры слоёв, для LSTM — окно, слои, Dropout, Dense и настройки обучения.
4. Для автоподбора выберите **Исследование диапазонов**, семейства моделей, количество вариантов и нажмите **Сгенерировать модели**, либо включите **Автоматическую оптимизацию**. Просмотрите варианты и запустите обучение. Исследование диапазонов использует random seed; автоматическая оптимизация выполняется с Optuna TPE.
5. Запустите схему кнопкой **«Выполнить эксперимент»**. После обучения выберите блоки анализа и объяснимости либо откройте **«Эксперимент» → «Результаты»** для полного набора графиков, валидационного сравнения, дневных метрик и экспорта.
6. Во вкладке **«Журнал»** можно посмотреть предыдущие запуски, скачать JSON и очистить записи. Текущий результат и библиотека датасетов при очистке сохраняются.

## Оценка и воспроизводимость

По умолчанию 60% train / 20% validation / 20% test. Победитель определяется по validation, метрики результата относятся к test. Увеличение числа кандидатов не затрагивает тест. При повторном ручном подборе по тестовым результатам нужна новая независимая финальная выборка.

Для временных рядов не перемешивайте наблюдения. Горизонт задаётся в строках, не в минутах. При неравномерных измерениях шаги могут соответствовать разным интервалам времени. При горизонте 0 модель оценивает текущую цель по текущим признакам. Лаги подразумевают пошаговый доступ к прошлым фактическим значениям.

Пропуски X заполняются на train; строки без Y исключаются. Некорректные даты можно исключать с предупреждением. Классификация требует достаточного числа объектов каждого класса. Категориальные признаки с более чем 200 категориями следует исключить или преобразовать; дату лучше преобразовать в календарные признаки. MAPE пропускает нулевые цели; это не «процент точности». R² может быть отрицательным.

Для экспорта доступны:

- `predictions.csv` — тестовые факты и прогнозы;
- `comparison.csv` — все кандидаты и validation-метрики;
- `experiment.json` — параметры, признаки, правила подготовки;
- `model.joblib` — обученный pipeline и конфигурация.

Пример использования собственного экспортированного артефакта (из корня проекта с установленными зависимостями):

```python
import joblib
from ml_lab.data import prepare_frame

artifact = joblib.load('model.joblib')
config = artifact['config']
# raw_df — DataFrame с теми же исходными колонками.
# Для непомеченных будущих данных не сдвигаем цель;
# сохранённый горизонт описывает время предсказываемого значения.
settings = dict(config['preparation'])
settings['horizon'] = 0
prepared = prepare_frame(raw_df, **settings)
y_pred = artifact['pipeline'].predict(prepared[config['features']])
```

Лагам нужны прошлые фактические Y. LSTM-артефакт содержит контекст перед тестовым блоком; при использовании на другом временном участке нужно передать корректный предшествующий контекст. Артефакты старых Keras-моделей из исходных папок автоматически не загружаются.

## Обновлённые страницы

**Данные и признаки.** Цель Y выбирается из списка, X — отдельными галочками в соседней области. Кнопки «Выбрать все» и «Снять все» управляют всем списком. Одна колонка времени или пара date + time преобразуется в единую типизированную колонку `datetime`; при наличии часового пояса время нормируется в UTC. Исходные файлы не перезаписываются.

Для отложенного прогноза можно выбрать последнюю долю набора, один день, диапазон дней или точный интервал дата + время. Обучение и валидация находятся раньше выбранного периода. При положительном горизонте границы относятся к датам целевых значений, а строки между частями исключаются на длину горизонта. Значения Y после выбранного конца не используются в обучении.

**Модель и обучение.** `ml_lab/model_registry.py` содержит 27 семейств: 21 модель регрессии и 17 моделей классификации, включая общие семейства. Есть поиск в выпадающем списке и фильтр по категории. В дополнение к прежним моделям доступны Elastic Net, Bayesian Ridge, Huber, SGD, Decision Tree, Extra Trees, AdaBoost, Bagging, Linear SVM, наивные байесовские классификаторы, дискриминантный анализ, GRU и RNN.

Режимы настройки:

- **Ручная настройка** — отдельные значения параметров, у MLP — размеры каждого слоя.
- **Исследование диапазонов** — заданные пользователем нижние/верхние границы, списки категорий, воспроизводимая случайная генерация и предварительный просмотр кандидатов.
- **Автоматическая оптимизация** — адаптивный подбор через Optuna TPE по валидационной метрике. Дополнительные семейства имеют собственные диапазоны. Лимиты итераций, эпох и длина окна фиксируются отдельно.

Под конфигурацией доступны копирование JSON штатной кнопкой блока кода, скачивание файла и просмотр `get_params()` установленного класса. Онлайн-каталог связан с официальными страницами scikit-learn/PyTorch и PyPI: кнопка проверки получает сведения о версиях. Это не загрузка исполняемого кода или новых алгоритмов из произвольного URL. Новые семейства добавляются в проверенный реестр с собственными диапазонами.

**Результаты.** Пять внутренних разделов: качество и прогноз, обучение и метрики, сравнение моделей, объяснимость, экспорт. Итоговые числа и дневные графики относятся к выбранному отложенному периоду; межмодельное сравнение и дневные сравнения — к общей валидации. Для единственной точки R² не определяется, но абсолютная ошибка доступна.

Объяснимость рассчитывается кнопками:

- **SHAP PermutationExplainer** — средние абсолютные вклады и локальные вклады выбранной строки; для классификации можно выбрать класс. Объясняются нормированные/one-hot признаки; для SVM без вероятностей используется decision_function. Фоновая выборка — train, объясняемые строки — validation.
- **Permutation Importance** — изменение MAE/F1 при перемешивании исходных X на ограниченной валидационной выборке.
- **Integrated Gradients** — приближённые вклады рекуррентных LSTM/GRU/RNN по временным окнам относительно нулевой точки в нормированном пространстве. Значения суммируются по шагам окна. Метод не называется SHAP.

Объяснения описывают поведение модели, а не доказывают причинность. Коррелирующие признаки могут делить вклад. SHAP ограничен 30 строками и 100 признаками после кодирования, чтобы сохранять управляемое время расчёта.

**Будущий прогноз.** Вкладка удалена из интерфейса. Модуль `ml_lab/forecast.py` сохранён как библиотечный API и проверяется тестами.

Источники API: [каталог scikit-learn](https://scikit-learn.org/stable/supervised_learning.html), [PyTorch](https://docs.pytorch.org/docs/stable/nn.html), [Optuna TPE](https://optuna.readthedocs.io/en/stable/reference/samplers/index.html), [SHAP PermutationExplainer](https://shap.readthedocs.io/en/stable/generated/shap.PermutationExplainer.html).

## Автоматическое время и точные размеры выборок

Готовая колонка `datetime` имеет приоритет, даже если в файле также есть `date` и `time`. Если её нет, время автоматически собирается из `date` + `time`. Подготовленный набор сортируется и получает `DatetimeIndex` с именем `datetime`. Выбора произвольных колонок времени в интерфейсе нет. Набор без времени сохраняет обычный индекс строк.

После подготовки времени автоматически создаются предикторы по исходным скриптам Nauchka/Nauchka-1: `calendar_hour`, `calendar_minute`, `calendar_dayofweek` (понедельник = 0), `calendar_quarter`, `calendar_month`, `calendar_dayofyear`, `calendar_day`, `calendar_weekofyear` (ISO-неделя). Сохраняются также sin/cos часа. Эти колонки видны в отдельном предпросмотре и выбираются галочками X наравне с исходными признаками.

На странице **Данные и признаки → Объём выборок** доступны:

- **Количество строк** — числовые поля обучения, валидации и теста; значения можно вводить с клавиатуры. При разделении по времени выбирается начало набора или последние доступные строки. Указанные размеры соблюдаются точно.
- **Проценты** — числовые поля долей теста и валидации, остаток относится к обучению.

Размеры относятся к строкам после исключения некорректных дат, неизвестной цели и недоступных выбранных лагов. Зазоры для горизонта выделяются дополнительно. Перед обучением показаны фактические размеры всех трёх частей и число оставшихся вне эксперимента строк. Если точная граница пересекает одинаковые даты, сайт просит изменить число строк, а не скрыто менять указанный размер.

При выборе тестового периода по датам число тестовых строк определяется этим периодом и показывается в поле без редактирования. Размеры обучения и валидации задаются вручную; их строки берутся непосредственно перед тестом. Если нужен тест с точным числом строк, выберите «Последняя часть набора» вместо календарного периода.

## Загрузка и библиотека датасетов

На вкладке **Данные и признаки** расположен раздел **Загрузка данных**. Можно загрузить несколько CSV, TSV или XLSX, настроить чтение и листы Excel, затем нажать **Использовать загруженные наборы**.

Загрузка сама по себе не сохраняет dataset в библиотеку: он находится только в текущей сессии. У каждого набора есть отдельная кнопка **Сохранить**, для нескольких файлов — **Сохранить все загруженные**. Сохранённые оригиналы и параметры чтения хранятся локально в `.local/datasets/`, исключённой из Git. Они доступны после перезапуска сайта. Повторное сохранение того же содержимого с теми же настройками не создаёт дубликат.

В источнике **Загруженные и сохранённые** выбираются нужные наборы для анализа. Для одного сохраняются исходные названия колонок. Для нескольких выбирается основной dataset и способ совмещения:

- **По datetime**: точное совпадение времени; сохраняются строки основного набора. Колонки остальных наборов добавляются по совпавшим датам, несовпавшие значения остаются пропусками. Повторяющиеся даты требуют предварительного устранения дубликатов. Автоматического усреднения или интерполяции нет.
- **По номеру строки**: требуется одинаковое количество строк и явное подтверждение, что строки соответствуют одним наблюдениям. Дата основного набора сохраняется, если она есть.

Название и короткий ID источника добавляются к именам колонок объединённого набора. Далее Y выбирается выпадающим списком, а X — галочками, включая признаки из разных датасетов. Состав выбранных источников и число совпавших дат показаны перед настройкой модели.

## Предобработка временного ряда и профиль MUF

В области «Цель и временная шкала» добавлены параметры подготовки ряда:

- **Строгая проверка полной даты** включена по умолчанию. Время без даты (`00:00`, `30:00`, `12:30:00`) всегда считается некорректным и не получает сегодняшнюю дату. Встроенный MUF содержит 26 таких строк; с включённым исключением плохих дат они удаляются при подготовке.
- **Единая сетка времени**: 5/15/30 минут, час или сутки. Добавленные точки остаются пустыми; неизвестная цель не заполняется и не интерполируется. Измерения вне выбранной сетки не округляются автоматически. Дубликаты можно отклонить либо явно оставить последнюю строку.
- **Лаги**: 1, 2, 3, 6, 12, 24, 48, 96 шагов. На сетке 30 минут лаг 48 означает ровно сутки; без сетки это только 48 предыдущих строк.
- **Скользящие окна**: среднее, стандартное отклонение, минимум и максимум за выбранное число шагов. Они считаются по `Y.shift(1)` с полным окном наблюдений. Последнее изменение — `Y[t−1] − Y[t−2]`. Текущая/будущая цель в эти признаки не попадает.

В X можно включить нужные сгенерированные признаки галочками. Строки, где выбранной истории недостаточно, исключаются до разделения на выборки; пропущенные исторические значения не заменяются медианой. Для признаков истории требуется разделение по времени. Для LSTM/GRU/RNN окна сбрасываются при разрывах доступной последовательности и дополняются первым доступным входом нового сегмента, не захватывая измерения до разрыва.

**Как попробовать MUF:** выберите набор MUF, нажмите **Настройки для MUF**, затем **Обучить и оценить**. Кнопка включает сетку 30 минут, лаги 1/2/3/6/12/48/96, среднее и стандартное отклонение за 6/12/48 шагов, последнее изменение и Hist Gradient Boosting. Горизонт 0 здесь означает оценку Y строки t по значениям до t, то есть при лаге 1 — пошаговый прогноз из предыдущего измерения. Все параметры профиля редактируются.

Календарные циклы учитывают минуты в дробном часе; дополнительно добавлены sin/cos годовой сезонности.

В «Результатах» показаны линия и метрики простого прогноза по предыдущему фактическому Y. Сравнение с моделью рассчитывается на одинаковых тестовых точках, где этот прогноз доступен; число точек указано явно. Эта оценка предполагает поступление фактических измерений по мере движения во времени. Она не означает такую же точность прогноза всего будущего интервала из одной точки. Для будущего блока без фактических Y модели с выбранными лагами или скользящими признаками требуют отдельной рекурсивной стратегии; текущий интерфейс не создаёт недостающую историю автоматически.

Настройки предобработки входят в экспорт конфигурации и используются при повторной подготовке данных.

### Предпросмотр фильтрации аномалий

В разделе «Данные → Восстановление пропусков и аномалий» доступны три модельных алгоритма: Isolation Forest, Local Outlier Factor и One-Class SVM. Настройте колонки и чувствительность, затем нажмите «Показать аномалии на графике». Оранжевая линия показывает исходные измерения, красные маркеры — кандидатов на коррекцию. Можно переключать колонки, увеличивать участок графика и просматривать значение и оценку точки при наведении. Все найденные аномалии включены в график, даже если линия прорежена.

Предпросмотр выполняет отдельный расчёт без применения восстановления к эксперименту. После изменения параметров постройте его заново. Для применения выберите способ коррекции и нажмите «Применить поиск и восстановление». Детекторы обучаются на прошлых измерениях; результат может отличаться от фильтрации всего ряда за один проход. Физические границы и дополнительная защита IQR также могут отмечать точки. Статистические методы IQR, MAD и Z-score сохранены.

### Три независимых этапа подготовки

В разделе «Данные» подготовка разделена на последовательные блоки:

1. **Аномалии**: Isolation Forest, LOF или One-Class SVM отмечают измерения; отдельный предпросмотр показывает маркеры. Только аномальные значения заменяются временной интерполяцией. Исходные пропуски сохраняются для второго этапа.
2. **Восстановление пропусков**: отдельный выбор Ridge, Random Forest, Extra Trees, градиентного бустинга, MLP, LSTM или GRU. По умолчанию включён автоматический выбор из трёх вариантов параметров по MAE на последних 20% известных измерений. Итоговая модель обучается на известных значениях выбранной колонки и временных/календарных входах. Обработка запускается автоматически после изменения настроек. Неудачные прогнозы и недостаток измерений компенсируются интерполяцией/ближайшим наблюдением; полностью пустая колонка выдаёт понятную ошибку. Счётчики отдельно показывают заполнения моделью и резервным методом.
3. **Признаки**: временные признаки, лаги, окна и статистики, EWM и разности выбираются из перечня. Каждая комбинация колонки, окна и статистики создаётся отдельным X. Рекомендации учитывают наиболее частый интервал дат и количество строк; кнопка выбирает предложенный набор. Исходные колонки доступны в перечне X.

При включении восстановления выбирается автоматический шаг сетки datetime: наиболее частая положительная разность уникальных отсортированных дат. Можно задать шаг вручную. Даты не округляются; если измерения не укладываются в сетку, требуется выбрать подходящий шаг. При включении восстановления повторные метки времени разрешаются сохранением последнего измерения — это можно изменить в настройках сетки.

Эти два этапа предназначены для **восстановления архива** и используют наблюдения с обеих сторон разрыва. Они отличаются от прежней причинной обработки `repair`, которая сохранена в Python для совместимости. Для независимой оценки прогнозирования нужно отключать архивное восстановление до обучения. Предупреждение отображается и в разделе моделей. Временная валидация подбора параметров служит ориентиром, а не гарантией качества на неизвестных значениях. Признаки истории по-прежнему сдвинуты в прошлое.

### Проверка меток и способов обработки аномалий

В первом этапе доступны Isolation Forest, LOF, One-Class SVM, Elliptic Envelope и статистические IQR, MAD, Z-score. Для модельных детекторов можно выбрать StandardScaler или RobustScaler; масштабирование обучается на прошлом опорном окне.

Переключатель «Метка точек для обработки» выбирает `−1` (обнаруженные выбросы, по умолчанию) либо `1` (обычные измерения, обратный выбор). У перечисленных sklearn-детекторов `−1` уже означает выброс: менять знак при смене модели не требуется. Статистические результаты приводятся к той же схеме. Неоценённые строки прогрева и отсутствующие значения не становятся нормальными автоматически; физические нарушения всегда остаются аномалиями. Для модельных методов используется итоговая классификация с существующей защитой IQR, а не необработанный вывод estimator.predict.

Выбранные точки можно заменить временной, линейной, полиномиальной второго порядка или PCHIP-интерполяцией, локальной медианой либо оставить как пропуски. Строки и datetime сохраняются; исходные пропуски не заполняются этим этапом. При невозможности полиномиального/PCHIP-расчёта применяется временная интерполяция с пояснением причины. На концах ряда интерполяционные методы используют ближайшую опорную точку. Предпросмотр показывает синюю исходную линию, оранжевый результат и красные выбранные точки. После изменения параметров его нужно построить заново. Визуальная проверка помогает заметить неправильный выбор, но не заменяет оценку по известным меткам.

Короткие пояснения оформлены обычным серо-синим текстом. Подробные объяснения вынесены в раскрывающиеся блоки. Архивный режим отмечен отдельной плашкой; поддерживается тёмная тема.

### Автоматическая настройка детекторов

В блоке аномалий включите «Автоматически подобрать настройки детектора». Для каждой выбранной колонки независимо проверяется до девяти сочетаний окна (64/128/256 наблюдений при достаточной истории) и чувствительности: contamination/nu 1%, 5%, 10% для модельных методов или порога 2/3/4 для IQR, MAD, Z-score. Остальные настройки выбранного алгоритма сохраняются. Подобранные окно и чувствительность заменяют ручные значения только в расчёте; итоговые параметры показаны в диагностике и предпросмотре. Метка класса и метод обработки не подбираются.

Проверка использует два временных блока, отдельные опорные и контрольные наблюдения и искусственные одиночные всплески разной амплитуды. Контрольные значения ограничиваются предварительным устойчивым диапазоном; это предположительно нормальные точки, а не истинная разметка. Выбирается максимальный F1 со штрафом за ложные срабатывания. Детектор не обучается на контрольных точках своего блока. Нужны минимум 96 конечных измерений в заданных физических границах; при недостатке истории или неудаче поиска сохраняются ручные параметры с пояснением.

Этот ограниченный поиск помогает подобрать отправную конфигурацию, но не гарантирует лучшую точность на естественных выбросах, сменах режима или длительных аномалиях. F1 относится только к синтетической проверке. Подбор использует архив и не сохраняет причинность старых результатов относительно будущих данных; для независимого прогнозного эксперимента он должен быть отключён вместе с архивной обработкой. Проверяйте выделение точек на графике.

В блоке аномалий режим выбирается переключателем «Автоматический подбор / Ручная настройка». Ручные параметры видны только в ручном режиме. График расположен сразу под настройками и автоматически обновляется после их изменения с небольшой задержкой; для повторного расчёта есть кнопка «Пересчитать». В перечне меток отображаются только `−1` и `1`. Подробные пояснения и результаты автоподбора раскрываются под графиком.

### Единый стиль интерфейса

Разделы используют заголовки 23 px, поля — названия 16 px и значения 16 px, короткие пояснения — 14–15 px с межстрочным интервалом 1.5, числовые показатели — 30 px. Основной цвет текста — #1E293B, пояснений — #64748B (в тёмной теме применяются контрастные аналоги). Карточки статистики имеют одинаковые отступы и высоту; на узком экране перестраиваются в две колонки, на телефоне — в одну. Пояснение к пустым ячейкам уточняет, что подсчёт относится к существующим строкам, а не отсутствующим моментам времени.

Восстановление включается переключателем справа от заголовка. Модель выбирается одним полем, столбцы — рядом; устройство модели, параметры и условия раскрываются отдельно. Временной индекс настраивается в «Параметрах времени». Результат переключается между графиком и таблицей. Все изменения оформления сохраняют существующие настройки обработки.

### Сохранение графиков и обученных запусков

Полный результат нового запуска, включая pipeline и прогнозы, сохраняется атомарно в `.local/runs/` и загружается при обращении после перезапуска API. Диагностические графики, объяснимость и экспорт больше не зависят только от памяти процесса. Сводное сравнение метрик train/validation/test строится из сохранённых значений браузера и остаётся доступным даже без серверного снимка.

Для старого запуска, созданного до сохранения полных результатов, доступна кнопка «Повторить расчёт по конфигурации запуска». Она создаёт новый запуск с сохранёнными настройками на текущей версии файла, а не восстанавливает потерянную обученную модель. Ошибки загрузки диагностики и расчёта объяснимости показываются раздельно. Отсутствие кривой обучения у модели не скрывает графики метрик по дням.

В графиках train, validation и test исходные измерения и восстановленные значения отображаются раздельно: восстановленные участки обозначены штриховой линией. Полные прогнозы строятся по подготовленной сетке, а метрики продолжают использовать только исходный факт. Старый запуск без временной сетки можно пересчитать с её восстановлением; запуск прежнего формата без сохранённых восстановленных целей для train/validation также требует обновления. Изменение черновика подготовки не изменяет уже обученную модель.

Сводный график метрик использует компактные столбцы, подписи значений, отдельные показатели для трёх выборок и пояснение направления улучшения. Единицы разных метрик не смешиваются на одной оси.

Дневные графики имеют два режима: «По подготовленным данным» включает восстановленные значения и показывает согласованность прогноза с подготовленным рядом; «По исходным измерениям» оценивает реальный факт и сохраняет неопределённые значения в дни без наблюдений. Итоговые показатели качества остаются рассчитанными по исходным измерениям. Метрики не интерполируются: для подготовленного режима они заново вычисляются по подготовленной цели. R² и MAPE могут быть неопределены по математическим причинам (например, недостаточно точек или нулевая цель).

При восстановлении пропусков отсутствие заданного шага включает автоматическую сетку по наиболее частому положительному интервалу исходных дат. Шаг фиксируется для всего набора и показывается в диагностике; тестами проверены 5, 15 и 30 минут. Несовместимые с сеткой даты не округляются молча. После выделения datetime служебные `index`, `level_0`, `Unnamed: 0` удаляются из подготовленных данных; datetime остаётся DatetimeIndex и не входит в X. В таблице результатов внутренний номер строки «Индекс» скрыт; он используется только для согласования выборок в вычислениях.

Предпросмотр аномалий выполняется независимо от других конфигураций подготовки: длительное восстановление не удерживает общую блокировку API. Совпадающие запросы используют один расчёт. Предпросмотр зависит только от настроек времени и детектора, а не от выбора признаков или параметров модели восстановления. До получения данных отображается состояние загрузки вместо пустых координатных осей; для запроса действует тайм-аут. Устаревшие ссылки на служебный `index` в колонках обработки и истории удаляются при нормализации сохранённых настроек.

### Анализ радиоканала: PACF, ApEn и спектр

После «Результатов» добавлена самостоятельная вкладка «Анализ радиоканала». Выберите числовую характеристику, исходные измерения либо текущую подготовку и запустите расчёт. Предварительная обработка применяется только к выбранному столбцу; признаки модели, горизонт и обучение прогнозной модели в анализ не включаются.

- **PACF**: частичная автокорреляция методом Дурбина–Левинсона по смещённой автоковариации; график лагов, их длительности и таблица значений. Пунктирные границы ±1.96/√N приблизительные, для отдельных лагов, без поправки на множественное тестирование.
- **ApEn**: приближённая энтропия с максимальной нормой, включением самосовпадений и натуральным логарифмом. Настройки m и r/σ, значение всего участка и график неперекрывающихся окон до 512 отсчётов. Допуск каждого окна рассчитывается по его стандартному отклонению. Сравнение осмысленно при одинаковой длине, параметрах, шаге и обработке; ApEn не имеет универсального порога качества канала.
- **Спектр**: метод Уэлча (Hann, 50% перекрытия) либо периодограмма. Ось частоты — циклы/сутки; плотность — единицы характеристики²/Гц. Таблица до пяти пиков содержит частоту в Гц, период в часах и число циклов на участке. Это спектр временного изменения характеристики, а не спектр радиочастотной несущей.

Для анализа нужен уникальный datetime. По наиболее частому шагу выделяется самый длинный непрерывный фрагмент без нечисловых значений; по умолчанию берутся его последние 4096 отсчётов (предел 8192). Время не склеивается через пропуски. Выбранные границы, шаг и число отсчётов отображаются явно; исходный анализируемый ряд можно раскрыть. Удаление среднего или линейного тренда применяется перед оценками. Постоянный ряд имеет ApEn = 0, неопределённую PACF после лага 0 и не имеет значимых спектральных пиков. Расчёт со всеми числовыми массивами выгружается в JSON.
